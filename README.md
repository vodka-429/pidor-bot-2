# Fake sublime telegram bot sources

![Tests](https://github.com/vodka-429/pidor-bot-2/actions/workflows/tests.yml/badge.svg)

This is _FAKE_ sources just **_imitating_** the functionality similar to the one by SublimeBot in Telegram

## Запуск локально

Нужны Python 3.13 (CI тестирует на 3.10) и PostgreSQL. Для базы можно поднять
`docker-compose up postgres`.

```bash
python -m venv venv && source venv/bin/activate
pip install -r requirements.txt
# .env: TELEGRAM_BOT_API_SECRET=<token>
#       DATABASE_URL=postgresql://postgres:postgres@localhost:5432/stb_db
alembic upgrade head
python3 main.py
```

Тесты: `pytest` (база не нужна).

## Конфигурация

Переменные окружения (читаются и из `.env`):
* `TELEGRAM_BOT_API_SECRET` — токен бота (обязательно)
* `DATABASE_URL` — строка подключения к PostgreSQL (обязательно)
* `GAME_CONFIG_PATH` — путь к JSON-конфигу чатов (см. `game_config.example.json`)
* `ALLOWED_FINAL_VOTING_CLOSERS` — кто может закрывать финальное голосование
* `BOT_HTTPS_PROXY` — исходящий прокси для Bot API и `getUpdates`

JSON-конфиг задаёт для каждого чата цены, награды, лимиты и feature flags; все
параметры описаны в docstring `GameConstants` (`bot/handlers/game/config.py`).
Боевой конфиг — `gameConfig` в `deploy/charts/app/values.yaml`.

## Деплой

Merge в `main` → GitHub Actions собирает образ в GHCR и коммитит его версию в
`deploy/charts/app/values-vdsina1.yaml` → ArgoCD выкатывает чарт. Миграции
alembic и меню команд применяются helm-хуком перед запуском.

## Новые функции

### Случайное время открытия розыгрыша

Настройка чата `random_start_enabled` (по умолчанию `false`) включает механику
сразу, без отдельной даты активации. В рабочем конфиге она включена только для
чатов `-1003932067905` и `-1001392307997`.

Если время ещё не назначено, новый розыгрыш доступен сразу. Уже сыгранный день
остаётся сыгранным: повторная команда возвращает прежний результат. Каждый успешный розыгрыш
выбирает на следующий календарный день равновероятный целый час от 00:00
до 18:00 МСК включительно и показывает его вместе с результатом. До этого
часа `/pidor` сообщает время открытия и оставшееся ожидание. Повторная команда
после розыгрыша показывает победителя и время следующего открытия.

Час сохраняется в БД вместе с результатом и наградами: рестарт, перевыбор
и повторные команды его не меняют. Если день пропущен, назначенный порог
уже истёк и следующий розыгрыш доступен сразу. Ограничения «24 часа после
прошлого запуска» нет; магазин и статистика используют прежние календарные дни.
Результат по-прежнему определяется ключом `(game_id, year, day)`, где `day` —
номер дня в году. Новое время используется только для допуска к запуску.

Новости ведутся реестром релизов (`RELEASES` в `changelog_service.py`, новая фича -
одна запись). В набор чата попадают включённые релизы не старше 30 дней (но не
меньше трёх последних). Первый `/pidor` показывает одним сообщением те из набора,
что ещё не показаны в чате; автоматической рассылки в полночь нет. `/pidornews`
показывает весь набор заново.

### Раз на раз и менты

Флаг чата `duel_enabled` (в коде по умолчанию `false`) добавляет в `/pidorshop` две кнопки.
В боевом конфиге включён для всех чатов (через `defaults`).

* `🥊 Раз на раз` — вызвать игрока, у которого баланс за всё время строго больше твоего.
  Ставка 2 / 5 / 10 / 20 койнов (не больше баланса), цель отвечает ставкой ×k, где
  k = баланс цели / твой баланс, но не больше ×3 (ставка цели округляется вверх и не
  превышает её баланс). Обе ставки списываются сразу, согласия цели не нужно.
  Разборка — на основном розыгрыше следующего дня: бот кидает кости за обоих (ничья —
  переброс), победитель забирает свою ставку и выигрыш, из выигрыша удерживается комиссия по ключевой ставке ЦБ.
  Перевыборы дуэли не переигрывают; если розыгрыша в тот день не было, ставки сгорают.
  Лимиты: один вызов в день от игрока, одна разборка на цель в день.
* `🚔 Вызвать ментов` — за 30 койнов отменяет все разборки на завтра (сегодняшние
  уже не отменить),
  обе ставки возвращаются без комиссии, новые дуэли на этот день создать нельзя.
  Один вызов на день разборок в чате, личный кулдаун 7 дней. Звонивший объявляется
  публично и один раз получает достижение «🚔 Мусорнулся» (без награды).

`duel_same_day: true` (только тестовый чат) привязывает новую дуэль к сегодняшнему
розыгрышу, если он ещё не прошёл.

### Вклады

Флаг чата `deposit_enabled` (по умолчанию `false`) добавляет в `/pidorshop` кнопку `💼 Вклад`.
Включён в тестовом чате `-1003932067905`. Потолок суммы — `deposit_max_amount` (200).

* Срок 7, 14 или 30 дней. Ставка — ключевая ставка ЦБ РФ в момент открытия (дальше не
  меняется); в игре это ставка за 30 дней: на 14 дней — половина, на 7 дней — четверть.
  Проценты округляются до ближайшего целого, без капитализации; минимальная сумма — такая, чтобы
  процент был не меньше 1 койна. Один открытый вклад на игрока.
* Проценты платит банк чата и резервирует их при открытии. Кнопки сумм показывают только те,
  проценты по которым банк покрывает; если не покрывает даже минимум — «Банк пуст, вклады закрыты».
* Выплата — одним платежом в конце срока при ближайшем `/pidor` (строкой в сообщении розыгрыша),
  а также при открытии `/pidorshop` и `/pidorcoinsme`. Досрочное снятие возвращает койны, проценты
  сгорают (возвращаются в банк).
* Вклад учитывается в богатстве для «Раз на раз» (кого можно вызвать и плечо), в годовом топе
  `/pidorcoinsstats` и при свопе койнов. Если у проигравшей цели не хватает койнов на руках, её
  вклад арестован до разборки (снять его и получить выплату нельзя), а проигрыш закрывает вклад
  досрочно без процентов. Менты снимают арест.

### Магазин пидор-койнов

Механики, статусы и баланс всех трат описаны в [`vibe/pidorcoins-economy.md`](vibe/pidorcoins-economy.md).

Команда `/pidorshop` показывает баланс, текущую комиссию и компактную клавиатуру. Кнопка `ℹ️ Что тут можно купить` открывает единый справочник:

* все включённые в текущем чате товары и действия;
* актуальные цены, награды и дневные лимиты;
* условия переводов, тостов, тотализатора и банка чата;
* пояснение, как комиссия входит в сумму списания и попадает в банк.

Справочник строится из конфигурации чата: отключённые функции в него не попадают.

### Растущая цена двойного шанса

Если в чате задан `double_chance_price_step` (например, 4), двойной шанс дорожает
для каждого следующего покупателя на того же игрока в тот же день: 8 → 12 → 16 🪙.
Другой игрок или другой день цену не меняют, шанс по-прежнему действует один день.
Цена видна на кнопках выбора игрока (`Имя ×2 · 16🪙`); если она выросла, пока вы
выбирали, бот сообщит новую цену и обновит кнопки. По умолчанию шаг 0 — цена плоская;
включено в чатах `-1003932067905` и `-1001392307997`.

### Драматические сообщения о пропущенных днях

Когда вы вызываете команду `/pidor`, бот теперь проверяет, сколько дней прошло с последнего розыгрыша. Если были пропущенные дни, бот отправит драматическое сообщение перед обычным розыгрышем. Уровень драматизма зависит от количества пропущенных дней:

* 1 день - легкое напоминание
* 2-3 дня - более серьезное предупреждение
* 4-7 дней - драматическое сообщение
* 8-14 дней - очень драматическое сообщение
* 15-30 дней - критическое предупреждение
* 31+ дней - апокалиптическое сообщение

### Система финального голосования

В конце года (29-30 декабря) доступна специальная система для распределения пропущенных дней:

**Команды:**
* `/pidormissed` - показывает список всех пропущенных дней в текущем году
* `/pidorfinal` - запускает финальное голосование (доступно только 29-30 декабря)
* `/pidorfinalstatus` - показывает текущий статус голосования

**Как работает взвешенное голосование:**
1. Голосование можно запустить, только если пропущено меньше `max_missed_days_for_final_voting` дней (по умолчанию 10)
2. Каждый игрок может проголосовать за любого участника
3. Вес голоса каждого игрока равен количеству его побед в текущем году
4. Победитель получает все пропущенные дни в свою статистику

**Пример:**
Если Игрок А выиграл 50 раз в году и проголосовал за Игрока Б, это считается как 50 голосов. Если Игрок В выиграл 30 раз и тоже проголосовал за Игрока Б, то Игрок Б получит 80 взвешенных голосов.


## Эксплуатация

### Надёжность long polling

Для Bot API и `getUpdates` используются отдельные HTTP-клиенты с явными таймаутами. Два независимых watchdog следят за polling-транспортом и последовательной обработкой updates. Если один `getUpdates` или один handler не завершается более 120 секунд, процесс пишет диагностические данные (для handler также стеки потоков) и завершается, чтобы Kubernetes перезапустил контейнер. Отдельный daemon-thread позволяет обнаружить даже синхронную блокировку event loop.

Helm Deployment использует стратегию `Recreate`: старый pod полностью останавливается до запуска нового. Это обязательно для long polling, поскольку Telegram допускает только один активный `getUpdates` на bot token.

Диагностические логи для команд, callback и магазинных черновиков содержат идентификаторы update/chat/user/message и этап операции, но не содержат пользовательский текст.

### Troubleshooting

**Проблема: Процесс работает, но бот перестал видеть новые команды и логи замолчали**
* Проверьте доступность Bot API через тот же `BOT_HTTPS_PROXY`, который использует приложение.
* Проверьте отсутствие второго pod или локального процесса с тем же token: в логах это проявляется как `Conflict: terminated by other getUpdates request`.
* Ищите `Telegram polling made no progress` или `Telegram update processing stalled`. Вторая запись содержит ID update/chat/user, тип операции и callback/команду; сразу после неё печатаются стеки потоков.
* Если Telegram преобразовал обычную группу в супергруппу, её ID изменится. Обновите `enabled_chats`, `test_chat_id` и `chat_overrides`, а перенос существующей игры задайте через `chat_migrations` в формате `{ "старый_id": новый_id }`.
* В Kubernetes должен использоваться `strategy.type: Recreate`; RollingUpdate временно запускает два poller и создаёт конфликт.
