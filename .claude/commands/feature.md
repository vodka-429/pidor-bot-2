Оркеструй разработку задачи: **$ARGUMENTS**

Ты — оркестратор (hub-and-spoke). Код сам не пишешь — делегируешь субагентам и собираешь результат. Контекст проекта — в `CLAUDE.md`.

## Цикл

0. **Своя ветка.** Проверь `git branch --show-current` и `git status`.
   - Если это `main` или ветка не под эту задачу — заведи свою от свежего main: `git fetch origin main && git checkout -b feat/<слаг> origin/main` (`fix/<слаг>` для исправлений).
   - Если в дереве есть **незакоммиченные чужие изменения** — остановись и спроси человека: значит, в этом каталоге работает кто-то ещё.

1. **Архитектура.** Запусти `architect` с задачей. Получи план, затрагиваемые файлы, применимые пункты чеклиста и **продуктовые развилки**. Совсем мелкую задачу (одна функция, текст, тест) можно провести без архитектора — реши сам.

   **Развилки — человеку.** Если architect вернул продуктовые вопросы с неочевидным ответом (тексты, поведение команды, цены/награды, в каких чатах включать, нужен ли анонс в `/pidornews`) — задай их через `AskUserQuestion` **до** запуска coder, по одному вопросу на развилку, с вариантами архитектора. Технические вопросы не выноси. Если человека нет (никто не отвечает) — выбери самый консервативный вариант (фича выключена по умолчанию и включена только в тестовом чате, без анонса) и явно отметь это в PR.

2. **Реализация.** Запусти `coder` с задачей, планом архитектора и ответами человека. Он пишет код и тесты, гоняет `pytest` до зелёного и коммитит в фиче-ветке.

3. **Ревью.** Запусти `reviewer` — независимо, без пересказа мнения кодера: только задача, план и ветка. Он читает дифф, сам перезапускает `pytest` и выносит PASS/FAIL.

4. **Итерация.** FAIL → передай замечания reviewer-а `coder`, затем снова `reviewer`. Максимум 3 итерации; если не сходится — остановись и доложи человеку, что именно не сходится.

5. **PR.** После PASS:
   - `git fetch origin main && git rebase origin/main` (CI коммитит в main bump образа), снова `pytest`;
   - `git push -u origin <ветка>`;
   - `gh pr create --base main` — заголовок в стиле conventional commits на английском; в описании: что сделано, ответы человека на развилки (или принятые по умолчанию решения), результат `pytest`, вердикт reviewer-а, что проверить руками в тестовом чате.
   - Если `gh` недоступен — запушь ветку и дай человеку ссылку на создание PR.

6. **Итог.** **Не мёржи и не деплой.** Доложи человеку коротко: что сделано, результат тестов, ссылка на PR. Merge (→ CI → ArgoCD) — решение человека: это гейт для прода и балансов игроков.

## Границы

Никаких мутаций `kubectl`/`helm`, `terraform apply`, `ansible-playbook`, ручных `alembic upgrade/downgrade`, push в `main` и force-push.
